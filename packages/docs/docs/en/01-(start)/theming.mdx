Utakata UI colors can be changed with CSS custom properties. You do not need to rewrite components or add another styling library.

## Try colors [#try]

You can edit all seven colors for light and dark schemes. The change applies to the examples inside Preview, with CSS and an initialization command containing your palette below. It does not affect the docs color scheme, and reloading restores the standard colors.

<Component path="en/theme" />

For source installation, check the Registry URL, copy the initialization command, and run it at your project root. The CLI saves the `light` / `dark` colors passed to `--palette` in `utakata.json` and generates `theme.css` in the target directory. Install the printed dependencies and import `theme.css` once from your global entry. Then add components with `utakata-ui add button`. If clipboard access fails, select the command field and copy manually. See [CLI installation](/en/registry).

`--palette` accepts partial maps of `primary`, `on-primary`, `surface`, `text`, `muted`, `border` and `danger`, using opaque `#RGB` / `#RRGGBB` values. Omitted colors retain their defaults. Colors are not adjusted automatically.

## Apply to your app [#apply]

Load the library styles in your global CSS, then write the overrides after them. If you [copied the source with the CLI](/en/registry), replace the import with a relative path to where `src/components/utakata/styles/styles.css` actually lives.

```css
@import "@utakata-ui/react/styles.css";

:root {
  --ui-color-primary: #6d28d9;
  --ui-color-on-primary: #ffffff;
}

@media (prefers-color-scheme: dark) {
  :root {
    --ui-color-primary: #c4b5fd;
    --ui-color-on-primary: #1e1535;
  }
}
```

By default the colors follow the OS light/dark setting. When you override them, set text and background colors as a pair for both light and dark. Overrides outside CSS layers take precedence over the library's `utakata.tokens` layer.

## Variables you can change [#variables]

| Variable | Purpose |
| --- | --- |
| `--ui-color-primary` | Primary actions and selected states |
| `--ui-color-on-primary` | Text and icons on the primary color |
| `--ui-color-surface` | Background of inputs, popups and similar |
| `--ui-color-text` | Body text and labels |
| `--ui-color-muted` | Supplementary descriptions |
| `--ui-color-border` | Borders |
| `--ui-color-danger` | Errors and dangerous states |
| `--ui-color-on-danger` | Text and icons on the danger color |
| `--ui-focus-ring` | Focus box-shadow |
| `--ui-radius-control` | Control corner radius |
| `--ui-shadow-popup` | Popup shadow |

Set your app's page background and body text color as needed.

```css
body {
  background: var(--ui-color-surface);
  color: var(--ui-color-text);
}
```

## Apps where users choose a theme [#user-selection]

Update `document.documentElement.dataset.brand` from the settings screen and switch colors on the root element. Setting it on the root lets the colors reach portals rendered under body, such as Dialog. Keep the initial SSR render fixed, and use browser APIs only in event handlers or client-side code.

```tsx
<label htmlFor="brand">Theme color</label>
<select
  id="brand"
  defaultValue="blue"
  onChange={(event) => {
    document.documentElement.dataset.brand = event.target.value;
  }}
>
  <option value="blue">Blue</option>
  <option value="violet">Violet</option>
</select>
```

```css
:root[data-brand="violet"] {
  --ui-color-primary: #6d28d9;
  --ui-color-on-primary: #ffffff;
}

@media (prefers-color-scheme: dark) {
  :root[data-brand="violet"] {
    --ui-color-primary: #c4b5fd;
    --ui-color-on-primary: #1e1535;
  }
}
```

Blue uses the standard colors as they are. This example does not save the choice. If you persist it, keep the choice usable where storage is unavailable, and design how the initial HTML reflects the saved choice in your app.

See [Dark mode](/en/dark-mode) to let users choose light, dark, or system.

## Checks after changing colors [#verification]

Check against 4.5:1 for normal text, 3:1 for large text and 3:1 for UI boundaries and states needed for identification, using the colors as composited on the actual background. The ratio above is computed from the two opaque colors you chose; it is not a verification of the whole screen.

In both light and dark, check normal, selected, error and focus states, keyboard operation, forced colors, and 200% text size with reflow. Do not convey errors or selection by color alone; combine color with wording or shape. Real-browser and screen reader verification of a custom theme is your responsibility, and these checks have not been performed on real devices for this sample.
