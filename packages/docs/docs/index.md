Utakata UI は、Base UI を基盤とし、内部で Lism CSS を使用する React・TypeScript の UI コンポーネントライブラリです。AI エージェントとともに UI を構築する **Agent Coding を前提**としています。

## Utakata UI が目指すもの

Utakata UI の主な目的は、**アクセシビリティを確実かつ十分に担保できるようにした上で、利用者がデザイン性のある UI を構築できる環境を提供すること**です。

必要な情報を受け取り、操作を理解し、目的の行動を完了できることを UI の土台とします。その土台を保ちながら、コンポーネントの組み合わせやデザインの選択を通じて、サービスに合った表現を実現できることを目指します。

### UI コンポーネントのコンセプト

- **アクセシビリティを部品の設計から組み込む。** 意味のある HTML、キーボード操作、フォーカス管理、名前や説明の関連付けを重視します。
- **アクセシビリティを保ちながらデザインできるようにする。** 共通の挙動を備えたコンポーネントとスタイルの仕組みを提供し、利用者がデザイン性のある UI を構築できるようにします。

### 提供・開発側の責務

このコンセプトを継続して実現するために、正しく実装し続けられる仕組みを整備・維持することは、Utakata UI の提供・開発側の責務です。

公開 Props の型制約、開発時の診断、CI の静的検査・実ブラウザー検証を組み合わせ、コンポーネントの品質を検証します。利用者の実装を支援する型や診断も提供側で整備し、必要な情報の欠落や誤った使い方を早期に見つけられるようにします。

## Agent Coding を前提とした利用

利用者が実現したい画面やデザイン、必要な操作をエージェントに伝え、エージェントが Utakata UI の公開仕様に沿ってコンポーネントを選択・組み合わせ、実装する使い方を想定しています。

Base UI の挙動と Lism CSS によるスタイルを Utakata UI のコンポーネントとして提供し、エージェントが共通の設計に沿って UI を構築できるようにします。[コンポーネント仕様](./components)と [MCP](./mcp)を通じて、公開 API、対応する Props、構成方法、アクセシビリティの品質要件を参照できます。

エージェントが実装に必要な情報を参照できるように、コンポーネント本体と仕様・品質要件を整合させて提供することも、提供・開発側の責務です。

## アクセシビリティ

目標は、適用される WCAG 2.2 のレベル A・AA の達成基準を満たすことです。部品側の挙動と検証に加え、利用側でも文言、ページ全体の構成、コンポーネントの組み合わせ、独自スタイルを確認することで、実際の画面のアクセシビリティを支えます。

提供・開発側では、自動検査に加え、実ブラウザーでのキーボード操作・フォーカス・コントラストや、スクリーンリーダーの読み上げを確認する検証手順を整備します。自動検査の成功は WCAG 適合全体を保証しません。
