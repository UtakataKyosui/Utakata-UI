title: Chartの採用判断
description: グラフライブラリの比較と、Chartを描画に依存しないシェルにした理由
---

shadcn/ui の Chart は Recharts を包んだ部品です。Utakata UI は本番依存を増やす前に確認する方針のため、ライブラリを選ぶ前に費用と適合性を比較し、その結果を決定として残します。

## 決定 [#decision]

- `Chart` は**描画ライブラリを同梱しない**アクセシブルなシェルとして提供します。`figure`・`figcaption`、テキストの説明、非色の系列識別つき凡例、データ表の代替、テーマと reduced motion のトークンを担います。
- 描画は `Chart.Plot` の中に利用側が置きます。インライン SVG、Recharts、visx、Chart.js のどれでも使えます。Utakata UI はどのライブラリにも依存しません。
- 組み込みのレンダラーは提供しません。系列数・軸・目盛り・凡例の対話などを持つと、公開 API とアクセシビリティの検証範囲が描画の仕様に引きずられるためです。
- 将来、特定のライブラリを任意のレンダラーとして加える場合は、本番依存の追加として事前に確認します（`AGENTS.md`）。

## 比較 [#comparison]

数値のサイズや版は変わるため、採用時に利用側で測定し直してください。ここでは構造上の違いに絞ります。

| 選択肢     | 描画       | 依存の費用                                                                         | アクセシビリティ上の注意                                                                      | 判断                                                         |
| ---------- | ---------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 手書き SVG | SVG（DOM） | なし                                                                               | 要素をすべて自前で用意する。軸・目盛り・スケール計算も自前                                    | 単純な折れ線・棒に向く。シェルの例で使用                     |
| Recharts   | SVG（DOM） | React 依存。内部で d3 系の部品を利用。部品数が多く、バンドルは中程度以上になりうる | `accessibilityLayer` などの支援はあるが、色以外の系列識別・データ表・凡例の文言は利用側の責任 | shadcn/ui と同じ。任意のレンダラーとして最有力。同梱は見送り |
| visx       | SVG（DOM） | 部品ごとに分かれ、必要分だけ取り込める。低レベルで組み立てる量が多い               | プリミティブのみで、アクセシビリティはすべて自前                                              | 細かく制御したい場合の選択肢。同梱は見送り                   |
| Chart.js   | Canvas     | 単体で動く。React 用ラッパーが別に必要                                             | Canvas は DOM を持たず、点ごとの情報は支援技術から見えない。代替のデータ表が必須              | 大量の点では有利。シェルのデータ表で補う前提                 |

## 描画に依存しない理由 [#rationale]

1. **検証の範囲を保てる**：シェルは自前の DOM だけで構成されるため、ブラウザーで検証できます（[検証ルール](/components/chart)）。ライブラリの内部 DOM は版ごとに変わり、保証範囲を広げられません。
2. **色以外の識別を共通化できる**：系列番号 1〜6 が色・マーカー形状・破線パターンを同時に決めるため、どのレンダラーでも同じ凡例と整合します。
3. **データ表を必須にできる**：Canvas を含むどの描画でも、値はデータ表で取得できます。キーボードでは `Chart.Data` の要約が Tab・Enter・Space で操作でき、表は `Table.Container` で横スクロールします。
4. **新しい本番依存を避けられる**：利用側が既に使っているライブラリをそのまま使えます。

## 既定値と対象外 [#scope]

- 既定値：データ表は閉じた状態、凡例は `ul`、系列色は `--ui-chart-series-1`〜`6`、破線は `--ui-chart-dash-1`〜`6`、アニメーション時間は `--ui-chart-duration`（既定 `200ms`、`prefers-reduced-motion` では `0s`）。ライト・ダークの両テーマで、系列色は背景に対して 3:1 以上になる値を使います。
- 利用側の責任：キャプション、データの傾向を述べる説明文、`Chart.Plot` の名前、データ表の内容と描画値の一致、描画ライブラリのアニメーションが `--ui-chart-duration` を読むこと、強制カラーモードで線や面が見分けられること。
- 対象外：ツールチップなどホバーに依存する情報（値はデータ表に置いてください）、`Chart.Plot` 内のフォーカス可能な操作（1 つの画像として公開されます）、軸・目盛り・スケールの計算、組み込みレンダラー、ズームやブラッシュなどの操作。
- 未検証：スクリーンリーダーの読み上げ、実際のブラウザーズーム 200%、実機での強制カラーモードは手動確認の対象で、実施するまで未検証です。
