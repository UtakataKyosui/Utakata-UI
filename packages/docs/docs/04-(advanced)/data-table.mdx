Utakata UI には、単一の `DataTable` コンポーネントはありません。既存の [Table](/components/table)、Pagination、Checkbox、Field、Button を組み合わせて作ります。状態の持ち方や取得方法は、利用側のアプリに合わせて選べるようにしているためです。このページは、その合成方法と責任の分担をまとめた手引きです。公開 API は追加していません。

## 責任の分担 [#responsibility]

表示側（Utakata UI の部品）はマークアップ・キーボード操作・フォーカス・名前と状態の公開を担います。データに関する判断は、利用側（サーバーまたはデータ層）が担います。

| 項目 | サーバー・データ層（利用側） | 画面の部品（Utakata UI） |
| --- | --- | --- |
| 検索 | 条件に合う行の絞り込み、総件数の算出 | `Field` + `Input` で入力を受け、値を呼び出し側へ渡す |
| ソート | 並べ替えと、その安定性・照合順序（日本語など） | `Button` で操作を受け、現在の列だけに `aria-sort` を付ける |
| ページング | 範囲外ページの補正、1ページ分の切り出し | `Pagination` で現在ページに `aria-current="page"` を付ける |
| 列表示 | 返すフィールドの決定（任意） | `Checkbox` で表示列を切り替え、空行の `colSpan` を合わせる |
| 行選択 | 選択の保存・一括操作の実行・権限確認 | `Checkbox` に名前を付け、選択数を `role="status"` で伝える |
| 読み込み中・エラー | 状態の判定と再試行 | 利用側が `Table.Root` の `aria-busy` や `Alert` で表示する |

この例の `queryInvoices` は、サーバーが行う処理の代わりです。`InvoiceTable` は受け取った `rows` を並べ替えたり絞り込んだりせず、そのまま描画します。クライアントで加工する構成（全件を取得してブラウザで処理する）も作れますが、その場合は加工後の結果を `InvoiceTable` に渡してください。表示の部品は、データがどこで加工されたかを区別しません。

## 構成 [#composition]

1. 検索: `Field.Root` > `Field.Label` + `Input type="search"`。ラベルは表示し、説明は `Field.Description` で関連付けます。
2. 列表示: ネイティブの `fieldset` と `legend`（例: 「表示する列」）の中に、`label` で包んだ `Checkbox` を並べます。行見出しになる列（例では番号）は切り替えの対象外にします。
3. 結果の状態: 件数・表示範囲・現在ページを `role="status"` の要素で示します。結果が空のときも同じ要素で「該当する請求がありません。」と伝えます。
4. 表: `Table.Container` > `Table.Root` > `Table.Caption`。名前は `aria-labelledby` でキャプションに結び付けます。
5. ページ送り: `Pagination.Root` に `aria-label` を付けます。

### ソート [#sorting]

- ソート可能な見出しの中に `Button variant="ghost"` を置き、列名を表示します。
- `aria-sort` は、現在ソートしている列の `Table.Head` だけに付けます。他の列には付けません。値は `ascending` または `descending` です。
- 例では「昇順 → 降順 → 解除」と切り替えます。▲▼ などの記号は見た目の補助で、`aria-hidden` にしています。状態は `aria-sort` が伝えます。
- 検索やソートの条件を変えたら、1ページ目に戻します。

### 空の結果 [#empty]

- `Table.Body` には、全列にまたがる1行（`colSpan` = 選択列 + 表示中の列数）を表示します。表そのものは消しません。
- 全選択のチェックボックスは無効にします。ページ送りは 1 ページとして残り、現在のページは `aria-current="page"` のままです。
- 列を非表示にしたときは、`colSpan` も合わせて更新します。

### 行選択 [#selection]

- 各行のチェックボックスには、行を特定できる名前（例: 「INV-001を選択」）を付けます。
- 見出し行のチェックボックスは「このページの請求をすべて選択」です。一部だけ選択されているときは `indeterminate`（`aria-checked="mixed"`）になります。全ページの選択ではありません。
- 選択は行の ID で保持します。ページや条件を変えても残り、「N件を選択中」は選択済みの総数を示します。条件の変更後に表示されない行が選択されたままになる場合は、その旨を画面に示すか、選択を解除する方針を決めてください。

### ページ移動後の状態 [#paging]

ページを移動しても、次の状態は維持されます。

- ソート列と方向（`aria-sort`）
- 表示列の選択
- 選択済みの ID と選択数
- 検索語

現在のページだけが変わり、`aria-current="page"` と表示範囲の文言が更新されます。URL で状態を持つ場合は、`Pagination.Link` の `href` をそのまま使い、`onClick` を使わずに通常のリンクとして移動させます。例のようにクライアント状態で切り替える場合は、`onClick` で `preventDefault()` を呼びます。

## 既定値と対象外 [#defaults]

- 1ページの件数は例では 4 件です。実際の値は利用側が決めます。
- ソートの初期状態はなしです。
- 選択はページをまたいで保持します。
- 仮想化、列の並べ替え・リサイズ、列固定、行の展開、インライン編集、複数列ソート、フィルター式の UI、ページサイズの選択、CSV 出力は対象外です。必要な場合は利用側で追加し、同じアクセシビリティ要件を満たしてください。
- 狭い幅でも列を隠さず、`Table.Container` の横スクロールを使います（Table の仕様に従います）。

## 利用側の責任 [#consumer]

- 取得した値のサニタイズ、権限確認、競合の解決。
- 読み込み中・エラー・再試行の表示。結果を更新したときにフォーカスを失わないようにすること。
- ページ送りの最後尾などで、フォーカスのある `Previous` / `Next` が無効になる場合の扱い。無効になるとフォーカスが失われるため、必要に応じて近くの有効なリンクへ移してください。
- ラベル・列名・状態名の翻訳と、表の目的に合った `Table.Caption`。
- 実際の見た目（コントラスト、ズーム、強制カラー、縮小モーション）の確認。

## 検証と未確認の事項 [#verification]

- 自動テスト（jsdom）で、空の結果、選択数、`aria-sort`、ページ移動後の状態、受け取った行を加工しないことを確認しています。axe は既定・ソート済み・空の状態で実行しています。
- 実ブラウザでのキーボード操作、スクリーンリーダーの読み上げ、各テーマのコントラスト、ズーム、強制カラー、縮小モーションは、この手引き単体では未検証です。
- 型は、ボタンのアイコンのみ利用時の名前などを静的に防ぎます。この例の `aria-label` の内容や `aria-sort` の付け方が正しいかは型では検証できません。実際のDOMで確認してください。
