# Utakata-UI implementation guide

Before writing UI, inspect `packages/react/src/metadata/manifest.ts` or use Blume MCP's `get_page` tool for `/en/components/<slug>` (Japanese: `/components/<slug>`). Use `search_docs` to find the component. Treat the manifest as the authority for supported component names, variants, defaults, composition, and accessibility requirements. The hosted docs follow the deployed version; inspect the installed `@utakata-ui/react/manifest` when working with another version. Do not invent props or substitute components that are not exported by `packages/react/src/index.ts`.

## Component usage

- Install the npm package with `pnpm add @utakata-ui/react` and import components from `@utakata-ui/react`. Only use `@utakata-ui/cli init` / `add` when the user explicitly asks to copy component source for modification; `init --registry <URL or directory>` saves defaults in `utakata.json` and copies shared CSS and LICENSE, then `add <name>` installs components. In a project that already contains copied source (for example `src/components/utakata/`), import from that location instead and do not add the npm package alongside it. The separate `@utakata-ui/cli a11y --config <path>` command checks declared color contracts without installing components.
- Import styles once from `@utakata-ui/react/styles.css`; it includes Lism CSS. Add `lism-css` as a direct dependency when importing its primitives directly. CLI `init` automatically installs Base UI and Lism CSS using the project's package manager; `--no-install` prints the command, and `--dry-run` changes neither files nor dependencies. Add the copied CSS import yourself.
- DOM-rendering components and parts accept Lism styling Props (`p`, `g`, `w`, `fz`, `bgc`, `layout`) and responsive values such as `w={{ base: '100%', md: 'auto' }}`. State-only roots, providers, portals and collections have no styling DOM. Existing component Props and accessibility constraints take precedence; use `ref`, not Lism's `forwardedRef`. Types `LismProps`, `LismStyleProps` and `WithLismProps` are exported. Reverify custom styling for contrast, focus, targets, reading order and reflow.
- Use `Button` for actions and provide a visible text label. For icon-only content set `iconOnly` and provide `aria-label` or `aria-labelledby`; this is enforced by TypeScript. `variant`: solid (default) | secondary | outline | ghost | destructive | link; `size`: sm | md | lg (no xs). Add `square` (only with `iconOnly`) for an equal-width icon target (32/40/48px). Use `destructive` only for dangerous actions with the consequence in the visible text, and confirm irreversible ones yourself (for example with `AlertDialog`). `variant="link"` is a text-styled action that stays a `<button>`; use a real `<a href>` for navigation. Resolve development name/reference warnings and validate computed names with axe. A warning-free render is not proof of accessibility.
- Compose `Field.Root` with a visible `Field.Label` and `Field.Control`. Add `Field.Description` or `Field.Error` when useful.
- Compose `Dialog.Root` with `Dialog.Trigger` and a portalled `Dialog.Popup` containing a `Dialog.Title`. Use Base UI's `Dialog.Close` and do not implement a second open-state or focus-management system.
- Use `Kbd` for each displayed key and `KbdGroup` for combinations. Key labels are supplied by you; when symbols such as `⌘` read poorly, set `aria-label` on `KbdGroup` and wrap the visual keys in `aria-hidden="true"`. Kbd does not register shortcuts.
- `Separator` is decorative (hidden from assistive technology) by default. Set `decorative={false}` only for meaningful separation; vertical separators stretch inside `Flex`.
- `Badge` is a static span for a status or category (`variant`: solid | outline | subtle (default) | destructive). Write the state in text; never rely on color. It has no role, focus or action. Use Button or a link for actions.
- `Skeleton` (`shape`: rect | circle) is always `aria-hidden`. Size it with `style` or `--ui-skeleton-width/height`. Put `aria-busy` on the loading region and one separate `role="status"` text, and set `aria-busy={false}` when content renders.
- `Spinner` renders `role="status"` with a visually hidden `label` (default `読み込み中`). Inside a Button use `decorative` and state the progress in the button text (`<Button disabled><Spinner size="sm" decorative />保存中</Button>`). `label` and `decorative` are mutually exclusive. Don't pass an empty label.
- `Card.Root/Header/Title/Description/Content/Footer` are static parts; all are optional. Set `Card.Title level` ('1'–'6', default '3', like Lism `Heading`) to fit the page outline. Do not make the card clickable; put Button or links inside.
- `Empty.Root/Title/Description/Actions` presents a static empty state. Set `Title level` to the page outline (default h3), compose named Button or link actions only when useful, and use a separate status region for dynamic announcements.
- `Alert.Root/Title/Description` (`variant`: default | destructive) adds no role by default. Set `role="alert"` only for urgent dynamically inserted messages, or `role="status"` for non-urgent ones. State the meaning (e.g. "エラー：…") in Title text; icons get `aria-hidden="true"`.
- `Avatar.Root/Image/Fallback` (`size`: sm | md | lg) wraps Base UI Avatar. `Avatar.Image` requires `alt`: the person's name, or `alt=""` plus `aria-hidden="true"` on `Avatar.Fallback` when the name is visible next to it. Initials are your Fallback children; `delay` postpones the Fallback.
- Compose `Progress.Root` with `Progress.Track` > `Progress.Indicator` and optional `Progress.Value`. A name is required by type: pass `label` (rendered as `Progress.Label`), `aria-label` or `aria-labelledby`. Use `value={null}` for unknown progress (NaN is also indeterminate), never `0`. Do not add live regions for each update; announce completion separately if needed.
- Use `Table.Container` > `Table.Root` with `Table.Caption`, `Table.Head scope="col" | "row"` and `Table.Cell`. `Table.Container` is the only horizontal scroller and is always a named, focusable region: give it `aria-label` or `aria-labelledby` (for example the caption id). Do not hide cells at narrow widths; use `colSpan` for empty-state rows. Sorting and pagination are your responsibility. For a data table (sort, search, column visibility, paging, row selection) compose `Table` with `Field` + `Input type="search"`, `Button variant="ghost"` inside sortable `Table.Head`, `Checkbox` and `Pagination`; there is no `DataTable` component. Search, sorting, totals and page slicing are server/data-layer work: render the rows you receive without re-sorting. Set `aria-sort` (`ascending` | `descending`) only on the currently sorted `Table.Head` and omit it elsewhere. Name every row checkbox (for example `aria-label="Select INV-001"`); the header checkbox selects the current page only and uses `indeterminate` for partial selection. Show the selected count and result range in `role="status"` elements. Render an empty result as one full-width row (`colSpan` = visible columns + selection column) with the table kept, and return to page 1 when search or sort changes. Keep sort, hidden columns and selection when changing pages; with URL state use real `Pagination.Link href`. Loading, errors, permissions and focus after updates are yours. See the "Composing a Data Table" guide in the docs.
- Compose `Breadcrumb.Root` > `Breadcrumb.List` > `Breadcrumb.Item` with `Breadcrumb.Link href` (or `render={<RouterLink />}`) and exactly one `Breadcrumb.Page` for the current location. Put `Breadcrumb.Separator` between items as a sibling; separators and `Breadcrumb.Ellipsis` are hidden from assistive technology. The default landmark name is 「パンくずリスト」.
- Compose `Pagination.Root` (name it with `aria-label`) > `Pagination.List` > `Pagination.Item` with `Pagination.Link href active`, `Pagination.Previous`/`Pagination.Next` and `Pagination.Ellipsis`. You own page state and URLs. Enabled Previous/Next require `href`; on the first/last page use `disabled` (no href, out of Tab order, clicks ignored). Do not put `Button` inside links.
- Use `Carousel` for one horizontal slide at a time. Pass `slides` with stable unique IDs and `labels` containing localized names and a 1-based position formatter. The component owns navigation, disables actions at both ends and keeps only the current slide interactive. It starts on the first slide, supports native swipe and viewport Arrow Left/Right/Home/End, and has no autoplay or wrapping. Provide alt text and meaningful names in slide content; define the formatter in a Client Component when using React Server Components.
- Use `Input` for single-line text inside `Field.Root` in place of `Field.Control` (never both); one input receives `Field.Label`, `Field.Description` and `Field.Error`. `size` is visual (`sm | md | lg`); set width with CSS. Provide `autoComplete` and visible error text; do not coerce values in the component.
- Use `Textarea` for multi-line text in place of `Field.Control`. Default `rows` is 3 and resizing is vertical; state `maxLength` limits in visible text such as `Field.Description`.
- Use `NativeSelect` for short single-value lists that should use the platform picker; pass `option`/`optgroup` children. `multiple` and the native listbox `size` are not supported; className/ref target the select.
- Compose `Checkbox.Root` with `Checkbox.Indicator` and name it with `Field.Label` in `Field.Root` or a wrapping `<label>`. An empty Indicator draws a check or a dash (indeterminate); do not pass a single ✓ glyph when using indeterminate. Base UI submits `name`/`value`; do not add hidden inputs.
- Compose `Switch.Root` with `Switch.Thumb` for settings that apply immediately; keep the label text unchanged across states. Use Checkbox for choices confirmed by a submit button.
- Use `RadioGroup.Root` with `RadioGroup.Item` (each containing `RadioGroup.Indicator` and its visible text) for a single choice. Name the group with `aria-labelledby` pointing at visible text, or `aria-label`; do not put it inside `Field.Root` with `Field.Label`, which would rename every item. `orientation` only changes layout. Keep the value on Root; `form.reset()` restores an uncontrolled `defaultValue`, and a controlled value must be reset in `onReset`.
- Use `Select` for a styled single-value listbox: `Root` (pass `items` so the trigger shows labels) > `Label`, `Trigger` (`Value placeholder`, `Icon`) and `Portal > Positioner > Popup > List > Item > ItemText` (+ optional `ItemIndicator`). The selected value is not a name; use `Select.Label`, `Field.Label` or `aria-label`. Use `NativeSelect` for native pickers. No multiple selection or search.
- Use `InputOTP.Root` for a one-time code inside `Field.Root` with `Field.Label` (or `aria-labelledby`), exactly `length` `InputOTP.Slot` parts and optional decorative `InputOTP.Separator`. `getSlotLabel` is required and names slots after the first (for example "Digit 2 of 6"); do not pass `aria-label` to Root or Slot. `autoSubmit` is not provided: submit with an explicit control, use `onValueComplete` only for follow-up work and verify the code on the server. Keep the default `autoComplete="one-time-code"`, `validationType` (`numeric` default) and paste support; show `Field.Error` text with how to recover. Use `Input` for passwords or free text.
- Use `Combobox` for a searchable single-value choice: `Combobox.Root` (pass `items` as `{ value, label }` objects; single selection only; control with `value`/`onValueChange`, which carry the item object) > `InputGroup > Input` (+ optional `Clear` and `Trigger`) and `Portal > Positioner > Popup > Empty + List > Item` (+ `ItemIndicator`), with `List` children as a function over the filtered items. Put `Combobox.Root` inside `Field.Root` and name the input with `Field.Label` (or a label element, `aria-label`, `aria-labelledby`); a placeholder is not a name and `Combobox.Label` is not provided. `Trigger` and `Clear` are pointer-only buttons outside the Tab order and require `aria-label` (type-enforced). Put a localized no-results message in `Combobox.Empty` and never hide it. Focus stays in the input; arrow keys move the highlight, Enter selects (not while an IME conversion is being confirmed), Escape closes the popup and, when already closed, clears the input and value. Free text that matches no item is never submitted. Do not add key handlers, chips, multiple selection, creatable or asynchronous options. Use `Select` for a short fixed list and `NativeSelect` for the native picker.
- Use `Command` for a searchable, always-visible list of commands (not a value picker): `Command.Root` (pass `items`, or groups of `{ value, items }`; the list is always inline, so there is no `open`, `name` or selected value) > `Panel > Input`, `Empty` and `List > Group (GroupLabel + Collection > Item)`, with `List`/`Collection` children as functions. Run a command from `Command.Item onClick` (pointer click and Enter on the highlighted item); it does not close anything by itself. For a command palette put `Command.Root` inside `Dialog.Popup` with a `Dialog.Title`, control `Dialog.Root` with `open`/`onOpenChange` and close it from `onClick` so focus returns to the trigger. Name the input with a label element, `aria-label` or `aria-labelledby` (a placeholder is not a name); put a localized no-results message in `Command.Empty` and never hide it. Focus stays in the input; arrow keys move the highlight, so add no key handlers. `Command.Shortcut` is a decorative hint (hide it with `aria-hidden` when a `Kbd`-style label is read elsewhere); opening the palette with Ctrl/Cmd+K is your responsibility and needs a non-shortcut alternative. Use `Combobox` to choose and submit one value, `Select` for a fixed list, and `DropdownMenu` for a small action menu.
- Use `Slider` with one `Thumb`: `Root` (number `value`/`defaultValue`, `min`/`max`/`step`, `onValueCommitted` for final values) > `Label`, `Value`, `Control > Track > Indicator + Thumb`. Use `format` or `getAriaValueText` when the bare number is not understandable.
- Use `Collapsible.Root` > `Collapsible.Trigger` (visible text) + `Collapsible.Panel` for one show/hide region. Control with `open`/`onOpenChange`; do not mirror state in `useState`. Closed content is unmounted (or hidden with `keepMounted`).
- Compose `Accordion.Root` > `Accordion.Item value` > `Accordion.Header level` > `Accordion.Trigger`, plus `Accordion.Panel`. `value`/`defaultValue` are arrays even in single mode; set `multiple` for independent items. Pick `level` (2–6, default 3) to fit the heading outline. Base UI 1.9 provides no arrow-key movement between accordion triggers; Tab moves between them.
- Use `Tabs.Root` with an explicit `defaultValue` or `value` (required by types), a `Tabs.List` named with `aria-label`, `Tabs.Tab`/`Tabs.Panel` pairs sharing `value`, and optional `Tabs.Indicator`. Activation is manual by default (`activateOnFocus` on List to change). Disabled tabs stay focusable but cannot be selected. Use links, not Tabs, for page navigation.
- Use `Toggle` (variant `outline | ghost`, size `sm | md | lg`) for a persistent pressed/unpressed option; keep the label constant because `aria-pressed` conveys state. Icon-only toggles need `iconOnly` with `aria-label`/`aria-labelledby` (type-enforced). It renders `type="button"` and never submits forms. Use `Button` for actions and a Switch for on/off settings.
- `Tooltip` shows short plain-text supplements on hover and keyboard focus (Escape closes; it stays open while hovered). Compose `Tooltip.Trigger` onto an existing control with `render` and give that control its own name; the popup is exposed as `role="tooltip"` and only describes the trigger. Never make the tooltip the only label or the only place essential information appears, and put interactive content in `Popover`. For a disabled action use `Button focusableWhenDisabled` so focus can reveal the tooltip. Place `Tooltip.Arrow` inside `Tooltip.Positioner` next to the popup.
- `HoverCard` (Base UI PreviewCard) shows a supplementary preview of a link on pointer hover and keyboard focus (Escape closes; it stays open while hovered; `delay` 600ms and `closeDelay` 300ms are Trigger props). `HoverCard.Trigger` is a link: `href` and link text (or `aria-label`) are required. The Popup is not announced, cannot take focus and is ignored for touch, so never put essential information or links/buttons in it; show them on the page or link target, and use `Popover` for interactive content. Place `HoverCard.Arrow` inside `HoverCard.Positioner` next to the popup.
- `Popover` is a non-modal popup for small interactive content. Always include `Popover.Title` (the popup's name), an optional `Popover.Description` and a `Popover.Close`. Base UI handles positioning, focus movement/return and Escape/outside dismissal; use `Dialog` for modal tasks.
- `DropdownMenu` lists actions (`Item`, `Group` + `GroupLabel`, `Separator`). Handle actions in `Item onClick`; selecting an item closes the menu and returns focus to the trigger. Use `disabled` for unavailable actions (still reachable with arrow keys, not activatable). Do not use it for site navigation; checkbox/radio items are not provided, and submenus exist only in `Menubar`.
- `ContextMenu` is a right-click / long-press / ContextMenu-key (Shift+F10) action menu: `ContextMenu.Root` > `Trigger` (a div area; put a focusable element such as a `Button` inside so keyboard users can reach it) and `Portal > Positioner > Popup`. `Popup` requires `aria-label` or `aria-labelledby` (no trigger button names it). `Item`, `Group`, `GroupLabel` and `Separator` are the DropdownMenu parts, so actions run in `Item onClick`, `disabled` items stay reachable by arrow keys, and Escape/selection restores focus. Never make it the only way to reach an action: touch users and many keyboard users do not discover right click or long press, so also offer the actions through a visible `DropdownMenu` or button. Submenus and checkbox/radio items are not provided.
- `Menubar` is a bar of several menus (File, Edit, View): `Menubar.Root` (required `aria-label` or `aria-labelledby`; `orientation`, `loopFocus`, `modal`, `disabled`) > one `Menubar.Menu` per menu > `Trigger` + `Portal > Positioner > Popup` with `Item`, `Group` + `GroupLabel`, `Separator`. The popup parts are the `DropdownMenu` parts. Nest with `SubmenuRoot > SubmenuTrigger` and a nested `Portal > Positioner > Popup`. The bar is one Tab stop; Base UI roves focus with arrow keys (Left/Right, or Up/Down when vertical), Home/End, Down to open, Right/Left for submenus, Escape to close. Add no tabIndex or key handlers. Handle actions in `Item onClick` (closes all menus and returns focus to the trigger); use `disabled` on `Menu` or `Item` rather than removing them. For right-to-left content wrap the bar in `DirectionProvider direction="rtl"` (exported from `@utakata-ui/react`) so the horizontal arrows swap. Do not use it for site navigation, use `DropdownMenu` for a single menu, and do not put form fields in popups. Checkbox/radio items are not provided; keyboard shortcuts and the page landmark structure are your responsibility.
- `NavigationMenu` is site navigation with links and panels of links: `NavigationMenu.Root` (required `aria-label` or `aria-labelledby`; `orientation`, `delay`, `closeDelay`) > `List` > `Item`. An `Item` holds either a `Link` or a `Trigger` (with an optional empty `Icon`, which draws a chevron) plus a `Content` of `Link`s. Put one `Portal > Positioner > Popup > Viewport` inside `Root` next to the `List`; Base UI shows the open `Content` there. Every `Link` needs `href` (or `render` with a router link that renders an anchor); mark the current page with `active` (it sets `aria-current="page"`, bolds and underlines it) and never pass `aria-current` yourself. Tab visits each link and trigger; Enter/Space/click/tap or hover opens a panel, Down opens it from the keyboard, Left/Right move between triggers (ltr only is verified), Escape closes and returns focus to the trigger. Panels stay open after a link is activated unless you set `closeOnClick` (useful for single-page routing). Add no `role="menu"`, tabindex or key handlers, and do not open panels only on hover. Use `Menubar` or `DropdownMenu` for commands and `Breadcrumb` for the current location.
- Use `AlertDialog` (same parts as `Dialog`) only to confirm important or destructive actions. Include `AlertDialog.Title` and `AlertDialog.Description`, put the cancel `AlertDialog.Close` first (or target it with `initialFocus` on `AlertDialog.Popup`) and run the confirming action from your own `Button`. It does not close on outside clicks; Escape and Close dismiss it. For asynchronous work keep `open` controlled and close after it finishes; there is no confirm Promise API.
- Use `Toast` for temporary status messages: wrap the app in `Toast.Provider`, render one `Toast.Portal > Toast.Viewport` (give it a localized `aria-label`) that maps `useToastManager().toasts` to `Toast.Root` with `Title`, `Description`, optional `Action` and a named `Toast.Close`, and call `manager.add/update/close`. Toasts are announced without moving focus; timers pause on hover/focus (default 5000 ms) and F6 moves focus to the viewport. Use `timeout: 0` for errors or toasts with an action, `priority: 'high'` only for urgent errors, update by `id` instead of repeating notifications, and never make a toast the only place an important action is available.
- Use `Sheet` (same parts as `Dialog`) for a modal panel attached to a viewport edge. `Sheet.Popup` takes `side` (top | right | bottom | left, default right; physical edges, no RTL flip) and an optional `--ui-sheet-size` custom property (width for left/right, maximum height for top/bottom). Include `Sheet.Title` (the popup's name), a useful `Sheet.Description` and a visible `Sheet.Close`. Base UI keeps the Dialog behavior (focus trap, Escape, backdrop press, focus return, scroll lock); long content scrolls inside the panel, so avoid fixed heights, and the slide transition is removed for reduced motion. `Sheet.Root` is always modal: its types reject `modal`. Use `Dialog` for a centered modal and `AlertDialog` to confirm destructive actions.
- Use `Sidebar` for site or app navigation that collapses: wrap the layout in `Sidebar.Provider` (`defaultOpen` true, or controlled `open`/`onOpenChange`, applies to wide viewports; `mobileBreakpoint` 768 px), render `Sidebar.Root` (a `nav`; name required by type: `aria-label` or `aria-labelledby`) with `Sidebar.Header`, `Sidebar.Content` > `Sidebar.Group` (`Sidebar.GroupLabel` names it) > `Sidebar.Menu` > `Sidebar.MenuItem` > `Sidebar.MenuButton href` (or `render` for a router link), and `Sidebar.Footer`. Put `Sidebar.Trigger` (a `Button`; an icon-only trigger needs `aria-label`; keep its label constant, `aria-expanded` carries the state) in the page content next to it, not inside the collapsible sidebar. Mark only the current page link with `current` (sets `aria-current="page"`, bold and a bar). Collapsed links are hidden from assistive technology and the Tab order; below the breakpoint the sidebar is a closed modal left `Sheet` with a visible close control (`closeLabel`, default "閉じる"), and focus moves to the trigger when a viewport change removes the focused element. `--ui-sidebar-width` sets the wide width (default 16rem) and `useSidebar()` returns `open`, `setOpen`, `isMobile`, `expanded`. You own the `main` landmark, skip link, routing, link destinations and any persisted open state (apply it before first paint). There is no icon rail, resize handle or keyboard shortcut. Use `DropdownMenu` or `Menubar` for actions, not navigation links in a menu.
- Use `Drawer` for a modal panel that touch users can also swipe away. `Drawer.Root` takes `side` (top | right | bottom | left, default bottom; physical edges, no RTL flip) and sets the matching swipe-to-dismiss direction; its types reject `modal`, `swipeDirection` and snap points. Parts: `Trigger`, `Portal`, `Backdrop`, `Popup` (renders the viewport and a scrollable content region itself; optional `--ui-drawer-size` custom property: width for left/right, maximum height for top/bottom), `Title` (the popup's name), a useful `Description` and a visible `Close`. Swiping is never the only way to close: always include `Drawer.Close` (Escape and backdrop press also close). Run irreversible actions from a `Button` click or keyboard activation, never on pointer or touch start, and confirm them with `AlertDialog`. Use `Sheet` for an edge panel without swipe gestures and `Dialog` for a centered modal. Real touch scrolling/swipe on phones and screen reader output are not covered by automated checks.
- Use `InputGroup.Root` to frame one existing `Input` or `Textarea` (inside `Field.Root` with `Field.Label`) with `InputGroup.Addon` (`align`: inline-start (default) | inline-end | block-start | block-end), `InputGroup.Text` and `InputGroup.Button` (a `Button`, default `variant="ghost"`, `size="sm"`, `type="button"`). `align` does not reorder: write start addons before the control and end addons after it. Hide decorative icons with `aria-hidden="true"` and link meaningful units to the input with `aria-describedby`. Give the button visible text; do not add a second input. Search, clear and password-visibility logic are yours.
- Use `ToggleGroup.Root` (name required by type: `aria-label` or `aria-labelledby`) with `ToggleGroup.Item value` (Toggle `variant`/`size`/`iconOnly`) for a set of toggle buttons. `value`/`defaultValue`/`onValueChange` are string arrays; `multiple` (default false) allows independent items, otherwise at most one is pressed and it can be cleared. `orientation` (horizontal | vertical) sets layout and arrow keys; the group is one Tab stop with Base UI roving focus. Use `RadioGroup` when one option must always be selected; no hidden inputs are submitted.
- Use `ButtonGroup` (name required by type: `aria-label` or `aria-labelledby`; `orientation` horizontal | vertical) to visually join related `Button`s. Buttons keep their own variant, size, disabled and type, and each stays a normal Tab stop; there is no toolbar or roving focus. Use `ToggleGroup` for pressed options.
- Use `Calendar` (name required by type: `aria-label` or `aria-labelledby`) to pick one day (`mode="single"`, default) or a range (`mode="range"`, value `{ from, to? }`). Dates are plain `"YYYY-MM-DD"` strings and months `"YYYY-MM"`; never pass `Date` objects (no time zones, no date library). Limit days with `minDate`, `maxDate` and `isDateDisabled` (disabled days stay focusable but cannot be selected); use `weekStartsOn` (0 = Sunday, default) and a BCP 47 `locale` (default `ja-JP`), and translate `labels` (`previousMonth`, `nextMonth`, `selected`) for other languages. Pass `today` for server rendering. Value and month are controlled with `value`/`month` or uncontrolled with `defaultValue`/`defaultMonth`. Not provided: right-to-left layout, multiple months, month/year dropdowns, week numbers, form submission, typed date entry (pair with an `Input`).
- Use `ScrollArea` for secondary content with intentional overflow. Provide one of `aria-label` or `aria-labelledby` and constrain the block size for vertical scrolling. Both axes use native scrolling and the named region is a Tab stop. Use `Table.Container` as the sole scroll region around a data table.
- Use `DatePicker` for single-day text entry and calendar selection in a form. Provide a visible `label` and a `name` for submission. Use ISO `YYYY-MM-DD` strings and `null` for no selection. `minDate`, `maxDate` and `isDateDisabled` apply to both typed and picked dates. Invalid text stays editable and blocks native submission. A form reset restores the initial `defaultValue`; controlled consumers receive the reset value through `onValueChange`. Translate `labels` and `calendarLabels` for non-Japanese interfaces and validate the date again on the server.

- Use the exported Lism CSS layout and typography primitives before creating custom layout wrappers.
- Responsive Lism values use ancestor container queries: place the layout inside `Box isContainer`. Standard CSS enables sm/md/lg at 480/800/1120px; xl requires custom Lism CSS configuration.
- There is no `AspectRatio` component. Keep a media ratio with `<Frame ar="16/9" w="100%">` around a direct `img`, `video` or `iframe` (`ar` also takes `{ base, md }`; no default ratio). The media fills the frame with `object-fit: cover`, and overflowing content is clipped, so put only media inside. Provide `alt`, `iframe` `title` and video captions/controls yourself and do not crop essential information. Types do not validate ratio strings.
- Customize appearance with CSS custom properties and classes; avoid runtime CSS generation.

## Verification

Prefer native HTML semantics. Check keyboard operation, visible focus, labels, descriptions, reduced-motion behavior, and dark theme contrast. Run `pnpm test`, `pnpm typecheck`, and `pnpm lint`; automated axe checks supplement rather than replace manual accessibility review.
